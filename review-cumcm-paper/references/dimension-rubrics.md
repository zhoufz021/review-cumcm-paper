## 使用方法

先判证据状态，再评分。`missing` 可评 0；`unverifiable` 不记 0；`not_applicable` 不进入分母。只根据本维度的证据定级，不用总印象补分。

固定权重：

| 维度 | 权重 |
| --- | ---: |
| 任务理解与覆盖 | 10 |
| 问题抽象与假设 | 8 |
| 数据处理质量 | 8 |
| 模型选择与适配 | 14 |
| 模型链与衔接 | 8 |
| 数学表达与推导 | 8 |
| 算法与求解 | 7 |
| 验证与稳健性 | 12 |
| 结果与可执行性 | 8 |
| 图表证据 | 6 |
| 正文写作与论证 | 7 |
| 可复现性与规范 | 4 |

通用等级含义：0=确实缺失或严重错误使本维度失效；1=形式存在但不能支撑结论；2=基本完成但有明显可信度缺口；3=较完整，主要证据能支撑结论；4=形成充分、可复核且说明适用边界的闭环。

## 1. 任务理解与覆盖（10）

**审核目标：** 判断论文是否按原题逐项回答了正确任务。

**必须检查：**

- 原题小问索引、每问输入、输出和评价标准；
- 摘要、正文、结论对每问的映射；
- 每问是否有模型/方法、结果和必要验证；
- 合并建模或跨问复用是否解释共享关系。

**不适用条件：** 只做与题意无关的版式检查时可不适用；全面审核中不得不适用。无原题属于无法核验。

**致命问题：** 理解了错误任务；遗漏决定性小问；输出对象、方向或约束与题意相反；用论文内部编号篡改原题小问。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 核心任务理解错误，或关键小问完全未答，主体结论不能回应原题。 |
| 1 | 罗列了小问或在摘要中声称回答，但正文缺模型、结果或关键任务映射。 |
| 2 | 大部分小问有回答，仍有一个重要输出、条件、评价标准或验证未覆盖。 |
| 3 | 所有小问均有明确方法和结果，主要条件与评价标准得到回应，少量接口说明不足。 |
| 4 | 建立完整小问矩阵；逐问闭环；共享模型、边界和跨问依赖均清楚且可回查。 |

**正面证据示例：** “Q3 要求在约束 C 下输出排班表；表 8 给出逐日排班，表 9 逐项核验 C，正文 p.16 解释可执行性。”

**反面证据示例：** 原题只有 3 问，论文出现“问题四”或“6 个阶段”，审核者据此报告 6 个小问。

**常见误判：** 按“问题一”关键词数量计小问；把一个摘要结果复制到多问；章节齐全即视为覆盖。

**置信度判定：** 原题与论文均清晰可读为高；原题在但局部 OCR 差为中；原题缺失为低且本维度无法核验。

## 2. 问题抽象与假设（8）

**审核目标：** 判断现实任务是否被转化为闭合、必要且可解释的数学对象。

**必须检查：**

- 决策、状态、观测变量与索引范围；
- 目标、约束、初始/边界条件；
- 假设的必要性、现实依据和失效影响；
- 数据或参数与变量的对应关系。

**不适用条件：** 仅做语言润色时可不适用；完整建模论文中通常适用。

**致命问题：** 目标对象定义错误；关键变量循环定义；假设与题面事实冲突；遗漏使解失真的硬约束。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 无可识别数学对象，或抽象、假设和题意存在根本冲突。 |
| 1 | 有变量或假设清单，但目标、约束、条件互不闭合，不能据此建立模型。 |
| 2 | 核心变量和目标基本明确，仍缺关键约束、边界、假设依据或失效讨论。 |
| 3 | 变量、目标、约束和主要假设闭合，假设与题意大体一致，少量现实简化未量化。 |
| 4 | 闭合定义之外，还解释每项关键假设简化了什么、何时失效及失效对结果的影响。 |

**正面证据示例：** 把库存守恒、产能、提前期和服务水平写入同一索引体系，并解释忽略换线时间的适用范围。

**反面证据示例：** 声称“忽略空气阻力”却在后续把阻力系数作为决策变量；或最小化成本但遗漏题面硬性安全约束。

**常见误判：** 假设越多越好；有符号表即闭合；文字中提到约束即等同数学约束。

**置信度判定：** 公式、符号、题面均可读为高；公式文本损坏但可视觉核验为中；关键公式/边界不可读为低或无法核验。

## 3. 数据处理质量（8）

**审核目标：** 判断数据是否被正确理解、诊断、清洗、变换并避免泄漏。

**必须检查：**

- 数据字典、单位、时间和粒度；
- 缺失、异常、重复、错位与样本选择；
- 处理规则的依据及处理前后影响；
- 训练/验证/测试隔离与数据泄漏；
- 外部参数来源和适用年份。

**不适用条件：** 题目完全由解析参数构成、无观测数据和外部估计时可不适用；参数来源转在可复现性中检查。

**致命问题：** 使用未来信息；训练测试泄漏；单位/列含义根本误读；删除或补值改变结论却未说明；伪造数据。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 数据含义或划分根本错误，处理使主要结论无效。 |
| 1 | 只写“清洗、标准化”，没有诊断、规则、数量或依据。 |
| 2 | 完成主要清洗和变换，但缺处理影响、泄漏检查、异常依据或分层诊断。 |
| 3 | 数据含义、质量诊断、处理依据和划分较完整，关键处理可回查。 |
| 4 | 在完整处理基础上量化处理影响、检查泄漏与偏差，并验证替代处理不会改变核心决策。 |

**正面证据示例：** 先按时间划分训练/测试，再仅用训练集估计标准化参数；表中报告缺失率、规则与样本数变化。

**反面证据示例：** 在全数据上选特征、归一化后再交叉验证；将“0”一律视为缺失而未核对数据字典。

**常见误判：** 图表多即处理好；调用软件函数即有依据；模型精度高可反证数据处理正确。

**置信度判定：** 数据字典、附件和处理记录齐全为高；只有论文描述为中；数据附件缺失且处理不可回查为低或部分无法核验。

## 4. 模型选择与适配（14）

**审核目标：** 判断模型是否由题意结构驱动，复杂度和适用条件是否合理。

**必须检查：**

- 题意结构与模型能力的对应关系；
- 候选方法及更简单基线；
- 选择理由、适用条件和参数可辨识性；
- 模型复杂度是否由数据量和任务需求支持。

**不适用条件：** 全面建模审核中不适用条件不存在。

**致命问题：** 模型与任务类型结构不匹配；用目标变量泄漏；适用条件明显不满足；模型无法产生题目所需输出。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 模型不能解决该任务，或违反关键适用条件使主结论失效。 |
| 1 | 只有模型/算法名称和公式，没有题意结构、选择理由或适用条件。 |
| 2 | 给出基本理由，但未比较简单候选、未检查适用条件，或复杂度证据不足。 |
| 3 | 题意结构、模型能力和主要适用条件对应清楚，选择基本合理。 |
| 4 | 除完整适配说明外，还用基线/候选比较、诊断或消融证明复杂度必要，并说明失效边界。 |

**正面证据示例：** 因存在整数批量、时序先后和容量约束选择混合整数规划，并与贪心基线比较可行性与目标值。

**反面证据示例：** “遗传算法全局搜索能力强，因此采用遗传算法”，但问题规模可枚举且没有编码、约束修复或基线。

**常见误判：** 高频模型等于必须模型；模型越新越好；引用文献即等于适配；公式复杂即有创新。

**置信度判定：** 原题、模型定义、参数和诊断均可读为高；只见方法描述为中；模型公式或关键输入不可读为低，若因此不能判断适配性则标记无法核验而非 0 分。

## 5. 模型链与衔接（8）

**审核目标：** 判断多个处理、模型和决策模块是否通过明确接口组成有效链条。

**必须检查：**

- 上游输出变量、单位、时间/空间粒度；
- 下游输入的引用位置和变换；
- 误差传播、口径一致性与共享参数；
- 独立模型合并或加权的依据。

**不适用条件：** 只有一个自足模型且不存在数据预处理、参数估计或后续决策接口时可不适用。

**致命问题：** 上下游变量含义、单位、时间范围或样本对象不一致；错误接口传播到主结论；循环依赖。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 链条接口错误或断裂，后续结果不能由前一步得到。 |
| 1 | 只按章节罗列多个模型或画箭头，没有接口变量和使用位置。 |
| 2 | 主要先后关系成立，但一处以上关键接口、尺度转换或误差传播不清。 |
| 3 | 上下游输入输出和主要变换明确，链条能复核，少量接口校验不足。 |
| 4 | 所有关键接口均定义、校验并讨论误差传播；共享与替代分支有明确依据。 |

**正面证据示例：** 回归输出的逐小时需求预测及区间成为优化模型的场景参数，并在约束表中使用相同单位。

**反面证据示例：** 聚类、预测、AHP、遗传算法依次出现，但聚类标签从未进入预测或优化公式。

**常见误判：** 模型名称共同出现即成链；流程图代替接口；章节顺序代替因果顺序。

**置信度判定：** 变量和表格接口均可定位为高；只可从上下文推断为中；关键表/公式不可读为低，无法确认接口时标记无法核验。

## 6. 数学表达与推导（8）

**审核目标：** 判断符号、公式、目标、约束、量纲和推导是否一致且足以复核。

**必须检查：**

- 符号唯一性、索引范围和单位；
- 公式来源、编号和正文引用；
- 关键推导步骤、边界/初始条件；
- 目标方向、约束符号和量纲；
- 特殊值、极限或等价变形。

**不适用条件：** 仅做版式快速预检时可不适用；全面建模论文中通常适用。

**致命问题：** 量纲不可能；目标方向或不等号错误；关键公式与定义矛盾；边界条件导致求解对象改变。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 关键数学表达错误或缺失，使模型无法成立。 |
| 1 | 有公式外观，但符号、索引、单位或逻辑无法连贯解释。 |
| 2 | 核心模型可辨识，仍有推导跳步、符号冲突、量纲或边界说明缺口。 |
| 3 | 关键定义、公式、目标、约束和主要推导一致，能够复核。 |
| 4 | 表达闭合且紧凑，并通过量纲、极限/特例或等价推导做内部校验。 |

**正面证据示例：** 先定义状态、控制、初值与终端约束，再从守恒关系推导离散方程，并给出量纲核对。

**反面证据示例：** 同一符号既表示概率又表示价格；分钟数据直接与小时容量相加。

**常见误判：** 公式多等于推导强；符号表存在即无冲突；LaTeX 美观等于数学正确。

**置信度判定：** 公式可视觉核验为高；文本层损坏但页面清晰为中；页面或公式不可读为低/无法核验。

## 7. 算法与求解（7）

**审核目标：** 判断从模型到数值解的流程是否正确、充分且可复核。

**必须检查：**

- 输入、输出、步骤、初值和参数；
- 编码、约束处理、停止条件和软件；
- 复杂度、收敛或稳定性；
- 随机算法的种子/重复策略；
- 解的可行性和最优性声明边界。

**不适用条件：** 全部结果由清楚的闭式解析推导直接得到时可不适用。

**致命问题：** 算法不能满足模型约束；停止前未得到可行解；把启发式结果无证据地称为全局最优；实现流程与模型不同。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 求解流程错误、不可执行或输出不是所定义模型的解。 |
| 1 | 只有算法名、软件名或流程图，没有关键参数和约束处理。 |
| 2 | 主流程可理解，仍缺初值、参数、终止、随机性、收敛或可行性检查。 |
| 3 | 流程、参数、约束处理和停止条件较完整，结果可复核。 |
| 4 | 在完整复现信息之外，还给复杂度/收敛/多初值或多次重复证据并界定最优性。 |

**正面证据示例：** 报告编码方式、种群规模、种子、约束修复、终止条件，并用多初值重复比较目标值。

**反面证据示例：** “用 MATLAB 求解得到最优方案”，未给求解器、模型传入方式、容差或可行性。

**常见误判：** 有代码即算法正确；收敛曲线即全局最优；软件默认值无需说明。

**置信度判定：** 代码、参数和输出映射齐全为高；只有正文算法为中；代码缺失不等于错误，但实现正确性无法核验。

## 8. 验证与稳健性（12）

**审核目标：** 判断模型、算法和决策是否经过与主张相匹配的验证。

**必须检查：**

- 验证对象；
- 基准、真值、实测、约束或解析特例；
- 指标、数据划分和结果；
- 误差结构与结论影响；
- 参数扰动、极端情景、失效边界或方案稳定性。

**不适用条件：** 纯定义性、无经验或决策主张的局部任务才可不适用；CUMCM 主模型通常适用。

**致命问题：** 用训练数据冒充外部验证；基准本身由同一输出生成；验证对象与主结论无关；已显示不可行仍维持结论。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 没有任何验证，或验证逻辑错误、结果直接否定主结论。 |
| 1 | 只有“合理、有效”、标题、拟合图或收敛图，没有完整验证链。 |
| 2 | 有误差、基准、可行性或敏感性，但对象、指标、数据、结果或影响不完整。 |
| 3 | 明确给出对象、基准/真值、指标、结果及其对结论的影响。 |
| 4 | 在完整验证上进一步检查参数扰动、极端情景、方案稳定性或失效边界，并说明决策是否改变。 |

**正面证据示例：** 用未参与拟合的时间段与朴素基线比较 MAE；按区域报告误差；扰动需求后检查排班仍可行且方案排序不变。

**反面证据示例：** 随机生成 1000 次样本后展示直方图，未说明验证对象、基准、指标或对方案的影响。

**常见误判：** 关键词命中即验证；随机模拟自动等于稳健；收敛验证模型正确；拟合优度等于预测能力。

**置信度判定：** 划分、基准、指标、结果均可回查为高；缺数据但正文链完整为中；只见标题/关键词或图不可读为低，验证对象或结果无法读取时标记无法核验。

## 9. 结果与可执行性（8）

**审核目标：** 判断结果是否直接、量化、条件明确且能用于题目要求的行动或判断。

**必须检查：**

- 逐小问关键数值或方案；
- 单位、精度、对象、时间范围和条件；
- 约束满足、现实解释和可行性；
- 摘要、正文、结论和附件的一致性；
- 路线、排班、阈值、矩阵等交付粒度。

**不适用条件：** 全面建模论文中不适用条件不存在。

**致命问题：** 没有回答主任务；结果违反硬约束；摘要与正文核心数值矛盾；方案无法执行。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 主结果缺失、错误对象或明显不可行。 |
| 1 | 只有定性趋势、“效果较好”或模型输出截图，不能回答题目。 |
| 2 | 有主要数值/方案，但缺单位、条件、逐问映射、可行性或现实解释。 |
| 3 | 逐问给出可用结果，条件、单位和主要约束清楚，能够执行或判断。 |
| 4 | 结果形成完整决策包，含方案细节、约束核验、不确定性/边界及附件映射。 |

**正面证据示例：** 给出每日车辆序列、开始时刻、资源占用和成本，并逐项报告时间窗与容量约束。

**反面证据示例：** 只报“最优利润为 128.6”，不写币种、周期、方案或约束满足。

**常见误判：** 有数值即结果充分；表格大即可执行；摘要数字可以替代正文解释。

**置信度判定：** 结果表、单位、条件和附件均可读为高；缺附件但正文完整为中；关键图表或单位不可读为低，无法确认核心结果时标记无法核验。

## 10. 图表证据（6）

**审核目标：** 判断图表是否可读、被正文使用，并承担探索、结构、验证或决策证据功能。

**必须检查：**

- 图/表号、标题、单位、坐标、图例、样本范围；
- 正文交叉引用与结论句；
- 图表与正文的数值、趋势和条件一致；
- 分辨率、颜色和必要标注；
- 图表功能而非数量。

**不适用条件：** 简单闭式推导且图表对理解、验证或交付均无必要时可不适用。

**致命问题：** 图表篡改尺度或内容与正文相反并支撑主结论；图表引用错位导致结果对象混淆。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 需要图表却完全缺失，或核心图表错误/矛盾使结论失效。 |
| 1 | 有截图或装饰图，但缺单位、图例、标题、引用和解释。 |
| 2 | 主要图表可读，但若干单位、引用、对照或结论解释不完整。 |
| 3 | 关键图表规范、被正文引用并明确支持主要判断。 |
| 4 | 图表体系覆盖数据、模型、验证和决策，设计紧凑，可直接复核关键结论与边界。 |

**正面证据示例：** 预测—实测图与残差图配套，正文引用并指出某时段系统性偏差及其对决策的影响。

**反面证据示例：** 无坐标单位的三维曲面，正文只写“结果见下图”。

**常见误判：** 图表数量多即高分；自动识别到“图1”即证据有效；美观等于可信。

**置信度判定：** 渲染页可清楚读取为高；OCR 只识别标题但图内不可读为低/无法核验。

## 11. 正文写作与论证（7）

**审核目标：** 判断文本是否以可复核顺序解释目的、依据、模型、求解、结果和验证。

**必须检查：**

- 摘要逐问信息；
- 章节功能、段落论点和前后指代；
- 公式/图表/结果的正文解释；
- 结论与正文一致；
- 事实、判断、引用和作者贡献的区分。

**不适用条件：** 全面论文审核中不适用条件不存在。

**致命问题：** 核心论证自相矛盾；摘要/结论与正文相反；关键来源或作者工作混淆到无法判断结论依据。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 论证无法追踪，关键段落矛盾或缺失，不能理解如何得到结论。 |
| 1 | 章节形式齐全但多为算法堆砌、公式罗列或主观评价。 |
| 2 | 主线基本可读，仍有关键跳步、重复、跨问混写或摘要/结论信息不完整。 |
| 3 | 目的—依据—模型—求解—结果—验证顺序清楚，主要内容前后呼应。 |
| 4 | 论证紧凑、证据就近解释、逐问闭环，并主动说明权衡、限制和适用边界。 |

**正面证据示例：** 每节先说明本问输出与选择依据，随后定义模型并在结果后立即解释验证和现实含义。

**反面证据示例：** 摘要只列 8 个算法名；正文公式连续出现但没有说明每个式子解决什么。

**常见误判：** 章节数多即结构好；语言流畅即论证充分；篇幅长即细致。

**置信度判定：** 全文可读且交叉引用可核验为高；OCR 断句多为中；段落顺序或公式引用不可读为低，无法判断论证关系时标记无法核验。

## 12. 可复现性与规范（4）

**审核目标：** 判断第三方是否能识别输入、参数、工具、代码/算法和输出来源，并核对引用与交付规范。

**必须检查：**

- 数据、参数和外部资料来源；
- 软件、版本/求解器、关键设置；
- 代码/伪代码、随机种子和文件清单；
- 附件与正文图表/结果映射；
- 参考文献、编号、单位和声明一致性。

**不适用条件：** 全面审核中维度通常适用；某个“代码”子项可因闭式解不适用。

**致命问题：** 关键参数无来源且决定结论；引用或附件错配使结果来源不可辨；声称提供的关键结果文件实际不存在。

| 分数 | 锚点 |
| ---: | --- |
| 0 | 关键输入、参数或方法来源缺失，主结果无法复现或追溯。 |
| 1 | 只写软件/算法名或“见附录”，缺输入、参数、文件或来源。 |
| 2 | 主要方法可追踪，仍缺关键参数、版本、随机性、附件映射或引用细节。 |
| 3 | 输入、参数、工具、算法/代码和主要输出映射完整，引用规范。 |
| 4 | 提供清晰文件清单、运行顺序、环境与结果校验，第三方可低成本复现关键结果。 |

**正面证据示例：** 附录列出数据文件、脚本、运行顺序、依赖版本、种子及每个输出对应的正文表图。

**反面证据示例：** “程序见附件”，但没有附件；外部参数只有数值，没有来源、年份或单位。

**常见误判：** 有参考文献即参数有来源；有代码页即能运行；未提供代码自动记 0。

**置信度判定：** 文件可访问并完成代表性运行为高；只有完整说明为中；缺附件时相关子项无法核验，但可见规范仍可评分。

## 总分与一致性

`加权分 = 权重 × 等级 / 4`。

`归一化总分 = Σ加权分 / 已评分权重 × 100`。

仅当已评分权重不少于适用权重的 80% 时输出总分。两次独立审核的维度差异超过 1 级时，必须回到具体证据和锚点，不得取平均掩盖分歧。
