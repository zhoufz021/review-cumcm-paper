## 1. 四态判定

每个检查项只能使用：

- `present`：有明确、可定位证据；
- `missing`：该项适用，经可靠通读与定向检查仍不存在；
- `not_applicable`：任务不需要；
- `unverifiable`：材料、OCR、公式、图表、代码或数据不足以判断。

搜索未命中不等于 `missing`。只有可读性足够、检查范围明确时才能判缺失。

## 2. 来源与定位

来源优先级：原题/附件 → 论文可见内容 → 论文代码/数据 → 官方要求/评阅要点 → 上轮报告 → 校准样本。

证据对象：

```json
{
  "id": "E001",
  "claim_type": "fact",
  "source_kind": "paper_text",
  "location": "PDF文件页序 p.12，§4.2，式(9)",
  "excerpt": "保持完整句意的短摘录或忠实视觉描述",
  "supports": "该证据支持的判断",
  "status": "present",
  "confidence": "high"
}
```

PDF 记录文件页序，若印刷页码不同可并列。DOCX 无稳定分页时记录标题路径、段落或表格。代码记录文件与行号。

## 3. 小问

原题是唯一主索引。论文“问题一”、模型编号、代码注释、表列、图号和附录号只作定位。合并建模保留原题所有 Q，并记录共享模型及接口。未提供原题时，任务数量和覆盖均为 `unverifiable`。

## 4. 验证

完整链：

`对象 + 基准/真值/约束 + 指标 + 结果 + 对结论的影响`

以下单独出现不构成完整验证：关键词、模型评价标题、作者声称合理、随机数、循环、拟合图、收敛图、单一拟合优度、没有决策解释的敏感性曲线。

验证质量需与主张匹配：

- 预测：样本外/时间回测、基线、分层误差；
- 分类：隔离、类别不平衡指标、阈值/校准；
- 优化：可行性、基线、界/收敛、多初值和情景稳定性；
- 机理：量纲、守恒、特例、步长/网格、实测或文献；
- 随机：分布依据、模拟收敛、尾部和相关性；
- 反演：已知样本、重建误差、噪声和参数敏感性。

## 5. 模型与模型链

模型选择证据回答：题意结构、模型能力、当前适配、简单候选、适用条件。算法名、软件名、公式和“经典/先进”表述不够。

模型链接口：

`上游输出变量（单位、粒度） → 下游输入 → 使用位置 → 变换/校验`

流程图箭头或章节先后不够。跨模型口径不一致时，记录其对后续结果的影响。

## 6. 结果与图表

结果证据应含小问、数值/方案、单位、条件、现实解释和可行性/验证。跨问复用必须解释共享关系。

图表检查图/表号、标题、坐标、单位、图例、样本范围、正文引用、结论句和一致性。截图、装饰图和无解释可视化不能评为高质量证据。文本抽取不可靠时回看渲染页。

## 7. 代码、数据与全局缺失

代码支持复现，不自动证明正确或稳健。随机代码需检查种子/重复、次数、收敛和输出解释。缺代码/数据标记 `unverifiable`，不推断实现错误。

判定“全文缺失”前：

1. 检查预期章节、相关小问、摘要、结论和附录；
2. 使用同义词和题型术语定向搜索；
3. 检查抽取稀疏页和图表页；
4. 必要时视觉核验；
5. 记录检查范围与搜索词。

全局缺失证据的 `location` 写为例如：“全文文件页序 1—26；检查 §3—§6、结论、附录；搜索‘误差/基准/敏感/验证/残差’”。不得虚构某一页。

## 8. 意见写法

按以下顺序写：

1. **事实：** 页面、公式或文件中可观察到什么；
2. **判断：** 与锚点或专项规则相比缺口是什么；
3. **推断：** 只有必要时说明可能后果，并标记不确定性；
4. **影响：** 对模型、结果、决策或复现的具体影响；
5. **修改：** 可执行动作；
6. **完成标准：** 下一轮可验证条件。

同一维度可同时有优点和局限，但对象与理由必须不同。不得按分数排序机械生成，也不得把同一理由写进两边。
